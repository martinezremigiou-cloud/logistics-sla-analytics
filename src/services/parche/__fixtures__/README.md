# Fixtures — `parche` (classification v2)

Everything in this folder is **invented sample data**, generated by
`scripts/generar-datos-muestra.mjs` (fixed seed, no network). There is no data
from a real operation. To regenerate it:

```
npm run datos:muestra
```

The test `src/services/etl/__tests__/datos-muestra.test.ts` fails if these
files stop matching what the generator emits.

## `productos-vivos-muestra.json`

A sample snapshot of the `productos` table (join `marcas(nombre)` +
`familias(nombre)`), with the same structure that this request would return:

```
GET /productos?select=sku,class,descr_origen,marcas(nombre),familias(nombre)
```

It is consistent with the sample workbook `muestra/clasificacion-parche.xlsx`
(sheets `Inventario` + `INV WEST`, the same shape as the unified workbook; it is
generated together with these files, and the `muestra/` folder is not
versioned). It carries the data-quality noise that the rules of
`clasificacion.build.ts` exercise: live values that are equal, padded with
spaces, in another case, different or empty; workbook SKUs with no live row
(`soloNuevo`); live SKUs with no row in the workbook (`soloViejo`), two of them
"garbage" with inner spaces.

## `constantes-parche.json`

A manifest of figures **by construction**: the generator counts them from its
own model (not from the builder) and the tests import them. It includes
cardinalities (rows, union, overlap, additions and removals), a witness SKU per
rule, how many live values differ from the file in each field, the expected new
catalogs, the normalization collisions and the live catalogs (brands, families,
aliases) that the context is built with.

## Use

- `clasificacion.build.integration.test.ts` loads the workbook and the fixture,
  builds `contexto.existingSkus` and `contexto.fuenteActual` (mapping
  `marcas.nombre` → `marca`, `familias.nombre` → `familia`) and compares every
  figure of the builder's report with the manifest.
- **It is not runtime data.** No endpoint or service reads it.
